## 一、改造总原则

1. **不重写，做语义迁移**：录制 → 转写 → AI 纪要 → 导出的 pipeline 是现成资产，整体平移给"面试记录"，改动集中在领域文案、数据字段、Agent 人设与流程。
2. **目录名尽量不动，动对外语义**：`minutes/`、`schedule/` 等目录重命名会引发 import 路径、Tauri command、样式引用的大面积改动，收益低。**第一阶段只改 UI 文案、类型定义、数据库字段**；目录重命名列为可选清理项（阶段末）。
3. **数据兼容优先**：`meetings` 表加 `kind` 列（`meeting` / `interview`），存量会议数据保留可查，不做破坏性迁移。
4. **Agent 是能力不是目的地**：模拟面试、简历分析这类对话场景走"面试助手"入口；复盘、点评这类操作以内嵌按钮 + 带上下文唤起。

## 三、数据模型变更（Rust `models.rs` + `repo.rs` 迁移）

```sql
-- ① meetings 表（面试语义字段，全部可选，兼容存量）
ALTER TABLE meetings ADD COLUMN kind TEXT NOT NULL DEFAULT 'meeting';   -- 'meeting' | 'interview'
ALTER TABLE meetings ADD COLUMN company TEXT;                            -- 公司
ALTER TABLE meetings ADD COLUMN position TEXT;                           -- 岗位
ALTER TABLE meetings ADD COLUMN stage TEXT;                              -- 'phone'|'online'|'onsite'|'mock'|'offer'
ALTER TABLE meetings ADD COLUMN score INTEGER;                           -- AI 评估总分（0-100）

-- ② scheduled_meetings（日程也分阶段）
ALTER TABLE scheduled_meetings ADD COLUMN stage TEXT NOT NULL DEFAULT 'phone';

-- ③ agent_conversations（角色化）
ALTER TABLE agent_conversations ADD COLUMN type TEXT NOT NULL DEFAULT 'general'; -- 'general'|'mock'|'review'|'resume'
ALTER TABLE agent_conversations ADD COLUMN ref_id TEXT;                          -- 关联 interviews/meetings.id（上下文注入用）

-- ④ 新增面试评估表（AI 输出结构化落库）
CREATE TABLE IF NOT EXISTS interview_assessments (
  id TEXT PRIMARY KEY,
  interview_id TEXT NOT NULL,      -- FK → meetings.id
  dimensions TEXT NOT NULL,        -- JSON：{专业技能,沟通表达,逻辑思维,岗位匹配,潜力}
  score INTEGER,
  summary TEXT,
  created_at TEXT NOT NULL
);
```

迁移方式沿用 `repo.rs` 现有的 `ALTER TABLE ... ADD COLUMN` 模式（参考 `schedule_id`、`pinned` 的写法），幂等可重跑。

## 五、Phase 2 — Agent 大改（核心）

### 5.1 人设与提示词（`py_backend/llm/prompt.py`）

- `system_prompt()` 删除"啤酒包装生产助手"，改为**面试助手**人设：
  - 职责：① 模拟面试官出题与点评；② 基于转写生成复盘评估；③ 简历分析与岗位匹配；④ 面试问题生成；⑤ 跟进待办管理。
  - 保留现有硬性要求（绝对日期、表格输出、`[待确认]` 标注、不编造）。
- 新增**分角色提示词**：`mock_prompt()` / `review_prompt()` / `resume_prompt()`，由 `chat.py` 按 `conversation.type` 选用。

### 5.2 对话角色系统（`chat.py` + `context.py` + `memory.py`）

| type | 行为 |
|---|---|
| `general` | 现有 ReAct 流程不变（人设换成面试助手） |
| `review` | 读 `ref_id` 对应的 meetings/transcripts/minutes → 摘要注入 system → 输出 ```` ```assessment ```` JSON → 落库 `interview_assessments` |
| `resume` | 上传简历文件（新增 .pdf/.docx 支持）→ 注入简历内容 → 输出改进建议 |
| `mock` | **新状态机流程**（见 5.3），不走标准 ReAct |

- `context.py`：`build_context` 增加 `conversation_type` / `ref_id` 参数，按类型注入领域上下文。
- `memory.py`：抽取 prompt 从"生产偏好"改为**求职档案**（目标岗位/意向城市薪资/面试进度/公司反馈/常犯错误）。

### 5.3 模拟面试流程（mock，重点新增）

**前端**（`AgentChat.tsx` 增加 mock 模式）：
```
[新建 mock 对话] → 填目标岗位 + 粘贴/输入 JD
→ Agent 流式出第 1 题（题目卡片，附考察点标签）
→ 用户文字作答（可计时）
→ Agent 点评 + 追问 / 下一题
→ 循环 N 轮（可配置，默认 5 题）
→ 用户点"结束面试" → Agent 生成总结评估（各维度打分 + 建议）
```

**后端**（`chat.py` 增加 mock 分支）：
- 会话状态存 `agent_messages`（role 标记 `mock_question` / `mock_answer`），不走多轮 ReAct；
- 出题阶段工具面收窄（仅 `question_bank` 可选列出历史真题，或纯 LLM 生成）；
- 结束时输出 ```` ```assessment ```` → 解析落库（`meetings.kind='interview' AND stage='mock'`）。

### 5.4 技能/工具系统（`py_backend/tools/handlers/`）

| 动作 | 工具 | 说明 |
|---|---|---|
| 保留 | `todo` | 跟进事项（投简历/刷题/感谢信） |
| 保留 | `xlsx` | 投递记录表 / 评分表 |
| 保留 | `execute_python` | 数据分析（各公司对比、通过率） |
| 降级 | `email` | 相关性低，从默认工具列表移除（保留实现） |
| **新增** | `interview_summary.py` | 读指定面试的转写/纪要（直连共享 SQLite） |
| **新增** | `resume_parse.py` | 简历解析（PDF/DOCX → 文本，新依赖 `pdfplumber` + `python-docx`，需评估 PyInstaller 打包体积） |
| 机制 | `registry.py` | `get_tool_definitions()` 增加按 `conversation.type` 过滤（如 mock 对话不暴露 `email`/`xlsx`） |

### 5.5 内嵌唤起（混合形态落地）

新增 Rust 命令 `agent_open_contextual(type, refId)`（或前端直接 `agent_create_conversation` + 首条消息预填），实现：
- 面试详情页"让 AI 深度复盘" → 创建 `review` 对话 + `ref_id` → 跳转 Agent 视图并自动发一条"请复盘这场面试"。
- 复盘报告页"生成面试问题" → 创建 `general` 对话 + 预填岗位上下文。

## 八、风险与注意事项

1. **录音合规**：录制真实面试（尤其线上面试的系统音频环回）涉及对方同意，录制面板必须加提示文案。
2. **旧数据兼容**：存量 meetings 按 `kind='meeting'` 保留，列表默认筛选 `kind='interview'`，设置项可"显示旧会议数据"。
3. **PyInstaller 打包体积**：新增 PDF/DOCX 解析依赖会增大 sidecar 体积，需在阶段 3 评估。
4. **mock 会话的 LLM 成本/延迟**：本地小模型（llama.cpp）出题质量有限，可优先走在线 API；状态机需处理用户中途退出。
5. **目录不重命名**：`minutes/`、`schedule/` 内部命名保留，靠文案和类型别名呈现面试语义；若坚持重命名，作为独立清理任务单独排期（影响所有 import 与 Tauri 注册）。
