## 一、项目与目标

把成熟的 Tauri v2 桌面应用 EasyWork（会议纪要 + 办公助手）重塑为**专门服务求职者面试备考**的「面试助手」。Python FastAPI 侧车进程（py_backend）共享 SQLite（WAL）；两条 LLM 路径：Rust 本地 llama.cpp（纪要/复盘）+ Python OpenAI 兼容/Ollama（agent 对话，SSE）。

已确认决策：① 用户定位=求职者备考；② Agent 形态=混合（主控台入口卡片 + 业务页内嵌 AI）；③ 主控台保持原风格（水滴气泡风已迭代定型）；④ 题库=AI 从面试转写提取面试官问题、用户勾选确认归档（**不是刷题工具**）；⑤ 简历全局资产（上传一次处处可用）；⑥ CRT 必须全链路 **/MD（动态）**，/MT 已被用户实测否决（运行时错误）。

## 四、未解决：Windows CRT 链接错误（rust-lld: /failifmismatch RuntimeLibrary）——完整调查档案

### 现象
```
rust-lld: error: /failifmismatch: mismatch detected for 'RuntimeLibrary':
  libwhisper_rs_sys-*.rlib(whisper.obj)  → MD_DynamicRelease（/MD 动态）
  libsherpa_onnx_sys-*.rlib(c-api.obj)   → MT_StaticRelease（/MT 静态）
```

### 根因（已查证）
- sherpa-onnx Windows 预编译库 **1.13.x 全系 /MT**：MT 命名（`*-win-x64-static-MT-Release-lib.tar.bz2`）由 commit `4f59df1`（2026-03-22, "Support static link for Rust package #3386"）引入；**v1.13.3 于 2026-06-15 发布**（commit 330609d），晚于该变更 → 1.13.3 的包就是 MT。
- whisper-rs-sys 0.15.0（Cargo.lock 锁定）用 CMake 编译 whisper.cpp，默认 /MD。
- 用户旧项目"动态成功"是因为下载缓存里是 MT 变更前的 /MD 预编译（同名资产后被重建替换）。
- **用户实测：/MT（静态）方案运行时错误；/MD（动态）运行成功。结论：必须全链路 /MD。**

### 已核实的技术事实（给接手模型省时间）
- whisper-rs-sys 0.15.0 build.rs：CMake 构建 whisper.cpp；**把所有 `WHISPER_`/`CMAKE_` 环境变量透传为 CMake 定义**（透传逻辑 commit `35aca74` 2026-06-07 加入，早于 0.15.0）。→ 设 CMAKE_* 环境变量即可影响 whisper.cpp 编译（但这正是被否决的 /MT 方向，勿再走）。
- sherpa-onnx-sys build.rs 支持 `SHERPA_ONNX_LIB_DIR`（直接用现成 lib 目录）与 `SHERPA_ONNX_ARCHIVE_DIR`（本地放**精确命名**的 tar.bz2 包）两个环境变量跳过下载。
- 旧独立仓库 `k2-fsa/sherpa-onnx-rust` 已删除（clone 报 "could not read Username"）；rust 绑定约在 v1.12.x 与 v1.13.3 之间并入主仓库。
- 本机/沙箱网络限制：外网 HTTPS 全被拦（curl/Invoke-WebRequest 失败），**只有 github.com 的 git 协议通**；npm/pip 正常。无法直接下载 crates.io 源码包（可试国内镜像但同样被拦）。

### 推荐修复方向（用户偏好 /MD）
1. **首选：降级 sherpa-onnx 到 1.12.x 最新版**（最后一个 /MD 预编译线）：
   - `src-tauri/Cargo.toml`: `sherpa-onnx = "1.12"`（去掉锁版本或更新 Cargo.lock 让 CI 重新解析）；
   - 代码用到的 API（`OfflineRecognizer/OfflineRecognizerConfig/VadModelConfig/SileroVadModelConfig/VoiceActivityDetector/SpeakerEmbeddingExtractor`）在 1.12.x 均存在且稳定，编译兼容风险低；
   - 验证方法：CI 日志里 sherpa-onnx-sys build.rs 会打印 `Downloading sherpa-onnx libs from <URL>`，确认下载的是**非 MT** 命名资产（`...win-x64-static-lib.tar.bz2`），且链接时 c-api.obj 变为 MD_DynamicRelease；
   - 注意：1.12.x 的 Windows 资产是否仍在线需 CI 验证（若 404 则走方案 2）。
2. **备用：保留 1.13.3，用 `SHERPA_ONNX_ARCHIVE_DIR` 喂 /MD 库**：下载 1.12.x 的 /MD 资产，重命名为 1.13.3 期望的包名（`sherpa-onnx-v1.13.3-win-x64-static-MT-Release-lib.tar.bz2`）放入 CI 缓存目录并设环境变量（内部 lib/*.lib 布局与文件名跨版本一致）。较 hacky。
3. **不推荐**：whisper → /MT（用户否决）、sherpa 源码编译（onnxruntime 太重）。
